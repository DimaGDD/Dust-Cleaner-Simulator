# 🚀 Инструкция по работе с Git

## 1. Начало работы

Проверяем, на какой ветке мы сейчас находимся:
```bash
git branch
```

Если находимся не на ветке `main`, переключаемся на неё:
```bash
git checkout main
```

Обновляем ветку `main` до актуального состояния:
```bash
git pull origin main
```

### Создание рабочей ветки
Перед названием ветки обязательно используем префикс, чтобы было понятно, какая задача выполняется:

* `feature/...` — новая механика или скрипт *(пример: `feature/magic-system`)*
* `bugfix/...` — исправление бага *(пример: `bugfix/magic-system`)*
* `refactor/...` — рефакторинг: переписываем код, чтобы стал чище *(пример: `refactor/magic-system`)*
* `chore/...` — рутина, обновление плагинов *(пример: `chore/update-cinemachine`)* *(скорее всего, не понадобится)*
* `release/...` — конечные изменения перед релизом игры *(пример: `release/update-settings`)* *(не понадобится)*

**Пример создания ветки:**
```bash
git checkout -b feature/magic-system
```

## 2. Работаем в проекте

Пишем код, настраиваем сцены и тестируем изменения в Unity.

---

## 3. Сохранение и отправка изменений

После завершения работы заливаем изменения в облако:

```bash
# 1. Добавляем все изменённые файлы для сохранения
git add .

# 2. Делаем коммит (описание изменений)
git commit -m "название коммита"

# 3. Заливаем ветку на сервер (вместо feature/magic-system укажите свою ветку)
git push -u origin feature/magic-system
```

### Правила оформления коммитов (Conventional Commits)
Используйте следующие префиксы в начале сообщения:

* `feat` — добавление новой игровой механики или функционала
* `fix` — исправление бага
* `chore` — рутина, настройка проекта, обновление плагинов
* `refactor` — чистка и переписывание кода без изменения функционала
* `docs` — изменение документации
* `style` — форматирование кода (отступы, пробелы, стиль)
* `perf` — оптимизация производительности
* `test` — добавление или исправление тестов
* `build` — изменение в системе сборки, настройка `.asmdef` или зависимостей
* `ci` — изменение в CI/CD
* `ui` — изменение интерфейса

**Примеры коммитов:**

```bash
# Коммит с названием в одну строчку
git commit -m "feat(magic-system): add magic-system"

# Коммит с заголовком и подробным списком изменений
git commit -m "feat(magic-system): add magic-system" -m "- Add magic-system core script" -m "- Add combinations in magic-system"
```

---

## 4. Создаём Pull Request (PR)

Открываем репозиторий на GitHub в браузере и создаём Pull Request из вашей рабочей ветки в ветку `main`.  
*(Сделаем вместе при первой отправке).*

---

## 5. Продолжаем работу

Чтобы приступить к новой фиче или исправлению бага, повторяем процесс с **Пункта 1**: переключаемся на `main`, обновляем ee и создаём новую ветку.

---

## 6. Удаление ненужной ветки

После того как ваш Pull Request будет проверен, влит в `main` и удалён с сервера, удалите старую ветку у себя локально:

```bash
# 1. Переключаемся на ветку main и обновляем её
git checkout main
git pull origin main

# 2. Очищаем локальный кэш от удалённых веток
git fetch --prune

# 3. Удаляем локальную ветку (подставьте название своей ветки)
git branch -d feature/magic-system
```
